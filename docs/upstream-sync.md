# مزامنة تحديثات ZCodium مع الحفاظ على هوية DeepCode Studio

DeepCode Studio نسخة معدّلة من [ZCodium](https://github.com/axiom-desu/ZCodium) (Apache-2.0). عندما يضيف المصدر ميزات أو إصلاحات، ندمجها بهذه الطريقة دون أن نفقد الاسم والشعار والعربية وحسابات DeepCode.

## كيف تعمل

كل يوم اثنين يعمل `.github/workflows/upstream-sync.yml`، ويمكن تشغيله يدوياً من تبويب Actions. يشغّل `scripts/upstream/sync.mjs` الذي:

1. يجلب `main` من ZCodium. إن لم يكن جديداً يتوقف.
2. ينشئ فرع `upstream-sync/<sha>` ويدمج التحديثات.
3. **يحل التعارضات الآلية وحده:** نحو 245 ملف واجهة غيّرناها فقط بسكربتات (تحويل الاتجاه لـ RTL، أسماء العلامة). إذا كان ملفنا = السكربت مطبَّقاً على النسخة القديمة من المصدر، فالحل = السكربت مطبَّقاً على النسخة الجديدة. هكذا تدخل تعديلات المصدر ويبقى تحويلنا.
4. **الملفات التي حذفناها عمداً** (خدمات Z.ai، بوتات Feishu/WeChat…) تبقى محذوفة، ويُذكر في التقرير أن المصدر عدّلها.
5. **ملفات CI** (`.github/workflows`) تبقى نسختنا، ويُذكر أي تغيير من المصدر للمراجعة.
6. يعيد تشغيل السكربتات على كل الشجرة، ويعيد توليد `config/provider/deepcode-builtin.json` من `zcode-builtin.json` الجديد، ويضيف أي نص واجهة جديد إلى `ar.ts` بالإنجليزية مع `// TODO(ar): translate`.
7. **دمج نظيف** ← Pull Request فيه قائمة مراجعة، ويبدأ فحص DeepCode (typecheck، lint، architecture، فحص تسرّب العلامة، اختبارات DeepCode) على الفرع.
   **تعارض حقيقي** (ملف عدّلناه يدوياً وعدّله المصدر في نفس المكان) ← Issue فيه قائمة الملفات.

لا شيء يصل للمستخدمين قبل أن تدمج الـ PR وتنشئ إصداراً.

## قائمة المراجعة في كل PR

- **مراجع جديدة لخدمات المصدر** (z.ai، bigmodel، cdn-zcode…): يجب ألا تُشحن. احذفها أو وجّهها إلى خادم DeepCode.
- **ملفات عدّلناها يدوياً وعدّلها المصدر**: تأكد أن الهوية والسلوك ما زالا صحيحين.
- **نصوص جديدة**: ترجم الأسطر المعلّمة `TODO(ar)` في `packages/ui/src/i18n/locales/ar.ts`.
- **الفحوص خضراء** في تبويب Actions لفرع الـ PR.

## عند وجود تعارض حقيقي (Issue)

```bash
git switch main && git pull
```

```bash
node scripts/upstream/sync.mjs
```

يترك السكربت الدمج مفتوحاً بعد حل الآلي منه. افتح الملفات المذكورة: خذ منطق المصدر الجديد وأبقِ أجزاء DeepCode (الأسماء، العناوين، `deepcode-account`، العربية). ثم:

```bash
git add -A && git commit
```

```bash
git push origin HEAD
```

وافتح PR من الفرع `upstream-sync/<sha>`.

## إيصال التحديث للمستخدمين

1. ادمج الـ PR في `main`.
2. أنشئ وسماً: `git tag v0.2.0 && git push origin v0.2.0`.
3. `deepcode-desktop.yml` يبني مثبّتات Linux/Windows/macOS وينشرها في Releases.
4. سجّل الملفات في `/admin/releases` في الموقع ← التطبيقات المثبّتة تكتشف التحديث من `/api/v1/releases/electron/manifest`.
   - Windows وLinux (AppImage): تحديث تلقائي.
   - macOS: يحتاج شهادة Apple Developer للتحديث التلقائي؛ بدونها يحمّل المستخدم النسخة الجديدة يدوياً.

## مهم: لا تسطّح تاريخ هذا المستودع

المزامنة تعتمد على أن تاريخ المصدر جزء من تاريخ هذا المستودع (لإيجاد نقطة الدمج المشتركة). لا ترفع هذا المستودع بتاريخ «جديد نظيف» ولا تستخدم squash عند دمج PR المزامنة — استخدم **Merge commit**.

## صيانة السكربتات

- `scripts/codemod/logical-classes.mjs` و`brand-strings.mjs` يجب أن تبقى **idempotent** (إعادة تشغيلها لا تغيّر شيئاً). `scripts/upstream/sync.test.mjs` يتحقق من ذلك على كل الشجرة في كل CI، ومن أن المعرّفات الداخلية ونص الإسناد «Based on ZCodium (Apache-2.0)» لا تُمس.
- إذا أضفت تعديلاً يدوياً على ملف واجهة كان آلياً فقط، سيصبح ذلك الملف «تعارضاً حقيقياً» عند أي تغيير من المصدر في نفس السطور — هذا مقصود.
